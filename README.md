# repodoctor

[![CI](https://github.com/jagadish-kumar-j/repodoctor/actions/workflows/ci.yml/badge.svg)](https://github.com/jagadish-kumar-j/repodoctor/actions/workflows/ci.yml)

repodoctor tells anyone who clones a repo what is missing on their machine to run it.

## Why

- You clone a new repo and lose an hour to a "works on my machine" failure.
- The README names a few tools but not the exact versions, ports, or environment variables.
- repodoctor reads the repo and tells you what to install or fill in before you start debugging.

## Install

Requires Python 3.10 or newer.
With pipx:

```bash
pipx install git+https://github.com/jagadish-kumar-j/repodoctor
```

For development on Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
.venv\Scripts\pytest
```

## Usage

Check the current directory:

```powershell
repodoctor check .
```

Real output from `repodoctor check tests/fixtures/docker_repo` (port states reflect the machine running it):

```
                                      Requirements
+--------------------------------------------------------------------------------------+
| Tool           | Required | Installed | Status      | Found in                       |
|----------------+----------+-----------+-------------+--------------------------------|
| docker         | -        | -         | MISSING     | Dockerfile, docker-compose.yml |
| docker-compose | -        | -         | MISSING     | docker-compose.yml             |
| port           | 3000     | free      | OK          | docker-compose.yml             |
| port           | 8080     | free      | OK          | docker-compose.yml             |
| port           | 5432     | in use    | PORT IN USE | docker-compose.yml             |
+--------------------------------------------------------------------------------------+
```

Get machine-readable JSON:

```powershell
repodoctor check . --json
```

Real output from `repodoctor check tests/fixtures/env_repo --json`:

```json
{
  "path": "tests/fixtures/env_repo",
  "ok": false,
  "requirements": [],
  "env": [
    {
      "variable": "SECRET_TOKEN",
      "status": "UNDOCUMENTED",
      "where": "app.py"
    },
    {
      "variable": "OLD_FLAG",
      "status": "UNUSED",
      "where": ".env.example"
    },
    {
      "variable": "API_KEY",
      "status": "MISSING",
      "where": ".env.example"
    }
  ]
}
```

Generate a setup script. It is written to disk (`setup.ps1` on Windows, `setup.sh` otherwise) and never run by repodoctor. Use `--force` to overwrite an existing file:

```powershell
repodoctor script . --shell powershell
```

Real output from running that command on `tests/fixtures/env_repo`, followed by the generated file:

```
Wrote setup script to setup.ps1
```

```powershell
# Generated by repodoctor. Review before running.


# Copy .env.example to .env if .env does not exist
if (-not (Test-Path .env)) { Copy-Item .env.example .env }

# Fill in the following variable names in .env:
#   API_KEY
```

## What it detects

| Check | Looks at | Example result |
| --- | --- | --- |
| Node | `package.json` (`engines.node`), `.nvmrc`, `.node-version` | `node \| >=18 \| v16.0.0 \| VERSION MISMATCH \| package.json` |
| Python | `pyproject.toml` (`requires-python`), `.python-version`, `requirements.txt` | `python \| >=3.10 \| 3.9.0 \| VERSION MISMATCH \| pyproject.toml` |
| Docker and compose | `Dockerfile`, `docker-compose.yml`, `docker-compose.yaml`, `compose.yml`, `compose.yaml` | `docker \| - \| - \| MISSING \| Dockerfile, docker-compose.yml` |
| Ports | Host ports in compose `ports:` entries; `PORT` / `*_PORT` in `.env.example` and `.env.sample` | `port \| 3000 \| free \| OK \| docker-compose.yml` |
| Environment variables | Keys in `.env.example` / `.env.sample`, set keys in `.env`, and usage in `.py`, `.js`, `.jsx`, `.ts`, `.tsx`, `.mjs` files | `API_KEY \| MISSING \| .env.example` |

## Exit codes

- `0` — no problems found.
- `1` — at least one failure status: `MISSING`, `NOT RUNNING`, `VERSION MISMATCH`, or `PORT IN USE`. A missing environment variable is also `MISSING` and causes `1`.

`UNDOCUMENTED`, `UNUSED`, and `UNKNOWN` are informational and do not change the exit code. `check` also exits `1` for a path that does not exist; `script` exits `1` for an invalid `--shell` or an existing output file without `--force`.

## Safety

- Detection only reads files in the target folder; it never executes scripts from that repo.
- The checker does run version/info commands against tools installed on your machine (for example `node --version`, `docker info`, `docker compose version`) and checks TCP ports on `127.0.0.1`.
- Only variable names are read from `.env`; values are never stored or printed.
- Generated scripts are written to disk only. repodoctor never runs them.

## Known limitations

- A port reported as `PORT IN USE` may belong to the project's own service already running, since repodoctor can't tell who is using it.
- Environment variable detection matches only these patterns: `os.environ["X"]`, `os.environ.get("X")`, `os.getenv("X")`, `process.env.X`, `process.env["X"]`, and `import.meta.env.X`, with UPPER_SNAKE_CASE names. Destructuring such as `const { X } = process.env` is not detected.
- Docker version is not checked; repodoctor only checks whether Docker is installed, whether it is running, and whether Compose is available.
- Monorepos are scanned as one folder; there is no per-package analysis.
- No macOS or Linux testing on real machines beyond CI. CI runs Ubuntu and Windows; local development has been on Windows.

## Contributing

Add a new detector as one file in `src/repodoctor/detectors/` exposing `detect(path: Path) -> list[Requirement]`, then import it and add it to the `detectors` list in `run_check()` in `src/repodoctor/check.py` (environment variables are handled separately).

Run the tests after installing the dev extra:

```powershell
.venv\Scripts\pytest -v
```
