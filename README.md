# repodoctor

[![CI](https://github.com/jagadish-kumar-j/repodoctor/actions/workflows/ci.yml/badge.svg)](https://github.com/jagadish-kumar-j/repodoctor/actions/workflows/ci.yml)

repodoctor tells anyone who clones a repo what is missing on their machine to run it.

## Why

- You clone a new repo and lose an hour to a "works on my machine" failure.
- The README names a few tools but not the exact versions, ports, or environment variables.
- repodoctor reads the repo and tells you what to install or fill in before you start debugging.

## Install

Requires Python 3.10 or newer.

With pipx:

```bash
pipx install git+https://github.com/jagadish-kumar-j/repodoctor
```

For development on Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
.venv\Scripts\pytest
```

## Usage

Check the current directory:

```powershell
repodoctor check .
```

Example output from `repodoctor check ./my-project` (port states reflect the machine running it):

```
                                      Requirements
+--------------------------------------------------------------------------------------+
| Tool           | Required | Installed | Status      | Found in                       |
|----------------+----------+-----------+-------------+--------------------------------|
| docker         | -        | -         | MISSING     | Dockerfile, docker-compose.yml |
| docker-compose | -        | -         | MISSING     | docker-compose.yml             |
| port           | 3000     | free      | OK          | docker-compose.yml             |
| port           | 8080     | free      | OK          | docker-compose.yml             |
| port           | 5432     | in use    | PORT IN USE | docker-compose.yml             |
+--------------------------------------------------------------------------------------+
```

For the HTML report, see the "HTML report" section below.

Get machine-readable JSON:

```powershell
repodoctor check . --json
```

Example output from `repodoctor check ./my-project --json`:

```json
{
  "path": "./my-project",
  "ok": false,
  "requirements": [],
  "env": [
    {
      "variable": "SECRET_TOKEN",
      "status": "UNDOCUMENTED",
      "where": "app.py"
    },
    {
      "variable": "OLD_FLAG",
      "status": "UNUSED",
      "where": ".env.example"
    },
    {
      "variable": "API_KEY",
      "status": "MISSING",
      "where": ".env.example"
    }
  ]
}
```

Generate a setup script. It is written to disk (`setup.ps1` on Windows, `setup.sh` otherwise) and never run by repodoctor. Use `--force` to overwrite an existing file:

```powershell
repodoctor script . --shell powershell
```

Example output from running that command on `./my-project`, followed by the generated file:

```
Wrote setup script to setup.ps1
```

```powershell
# Generated by repodoctor. Review before running.


# Copy .env.example to .env if .env does not exist
if (-not (Test-Path .env)) { Copy-Item .env.example .env }

# Fill in the following variable names in .env:
#   API_KEY
```

## HTML report

```powershell
repodoctor check ./my-project --html report.html
repodoctor check ./my-project --html report.html --force
```

The HTML report is one self-contained file. It contains no scripts, external links, external stylesheets, fonts, or images. Values from repository and machine results are HTML-escaped before they appear in the report.

## AI explanations (optional)

Install the optional AI dependency:

```bash
pip install "repodoctor[ai] @ git+https://github.com/jagadish-kumar-j/repodoctor"
```

For development:

```bash
pip install -e ".[ai]"
```

```bash
repodoctor explain ./my-project
repodoctor explain ./my-project --dry-run
```

Ollama is used with `--provider ollama` (the default). Set `REPODOCTOR_MODEL` to choose the Ollama model; it defaults to `llama3.2`. An OpenAI-compatible service can be used with `--provider openai-compat`, `REPODOCTOR_AI_URL`, `REPODOCTOR_AI_KEY`, and `REPODOCTOR_MODEL`. API keys come only from environment variables.

The AI receives only tool names, required and installed versions, statuses, port numbers, and valid environment variable names matching `^[A-Z][A-Z0-9_]{0,63}$`. It never receives the folder path, file contents, `.env` values, or other repository text. `--dry-run` prints the exact JSON payload and sends nothing.

Fix commands come from fixed templates in the code, not from the model. The model writes only a short summary. Small models can produce weak summaries, and users should still verify template commands before running them. The tool itself never executes a suggested command.

## What it detects

| Check | Looks at | Example result |
| --- | --- | --- |
| Node | `package.json` (`engines.node`), `.nvmrc`, `.node-version` | `node \| >=18 \| v16.0.0 \| VERSION MISMATCH \| package.json` |
| Node packages | `dependencies` and `devDependencies` from the top-level `package.json` compared with `package.json` files in `node_modules` | `npm: express \| ^4.0.0 \| 3.0.0 \| VERSION MISMATCH`; `node packages \| 5 of 5 OK` only when no package is `MISSING` or `VERSION MISMATCH` |
| Python runtime | `pyproject.toml` (`requires-python`), `.python-version`, `requirements.txt` | `python \| >=3.10 \| 3.9.0 \| VERSION MISMATCH \| pyproject.toml` |
| Python packages | Top-level `requirements.txt` compared with `*.dist-info` folder names in an inside-folder `.venv` or `venv` | `pip: flask \| >=3.0 \| 2.9.0 \| VERSION MISMATCH \| requirements.txt`; `python packages \| 5 of 5 OK` only when no package is `MISSING` or `VERSION MISMATCH` |
| Docker and compose | `Dockerfile`, `docker-compose.yml`, `docker-compose.yaml`, `compose.yml`, `compose.yaml` | `docker \| - \| - \| MISSING \| Dockerfile, docker-compose.yml` |
| Ports | Host ports in compose `ports:` entries; `PORT` / `*_PORT` in `.env.example` and `.env.sample` | `port \| 3000 \| free \| OK \| docker-compose.yml` |
| Environment variables | Keys in `.env.example` / `.env.sample`, set keys in `.env`, and usage in `.py`, `.js`, `.jsx`, `.ts`, `.tsx`, `.mjs`, `.cjs`, `.go`, `.java`, `.rb`, and `.rs` files | `API_KEY \| MISSING \| .env.example` |

## Exit codes

- `0` — no problems found.
- `1` — at least one failure status: `MISSING`, `NOT RUNNING`, `VERSION MISMATCH`, or `PORT IN USE`. A missing environment variable is also `MISSING` and causes `1`.

`UNDOCUMENTED`, `UNUSED`, and `UNKNOWN` are informational and do not change the exit code. `check` also exits `1` for a path that does not exist; `script` exits `1` for an invalid `--shell` or an existing output file without `--force`.

## Safety

- Detection only reads files in the target folder; it never executes scripts from that repo.
- The checker does run version/info commands against tools installed on your machine (for example `node --version`, `docker info`, `docker compose version`) and checks TCP ports on `127.0.0.1`.
- Only variable names are read from `.env`; values are never stored or printed.
- Generated scripts are written to disk only. repodoctor never runs them.

## Known limitations

- A port reported as `PORT IN USE` may belong to the project's own service already running, since repodoctor can't tell who is using it.
- Environment variable detection recognizes UPPER_SNAKE_CASE names in Python (`os.environ`, `os.environ.get`, `os.getenv`, `os.environ.setdefault`), JavaScript/TypeScript (`process.env`, bracket access, `import.meta.env`, and object destructuring), Go (`os.Getenv`, `os.LookupEnv`), Java (`System.getenv`), Ruby (`ENV`, `ENV.fetch`), and Rust (`env::var`, `std::env::var`).
- Python package checking only reads top-level `requirements.txt`; it does not read dependencies from `pyproject.toml`. It only searches an inside-folder `.venv` or `venv`, reads `*.dist-info` folder names, and never runs the venv's Python or pip executable.
- Node package checking reads `dependencies` and `devDependencies` from the top-level `package.json`, compares them with `node_modules` by reading files, and never runs npm or node. It does not read lockfiles, does not support workspaces or monorepos, and skips specs that are not semver ranges.
- Docker version is not checked; repodoctor only checks whether Docker is installed, whether it is running, and whether Compose is available.
- Monorepos are scanned as one folder; there is no per-package analysis.
- Not tested on macOS. CI runs Ubuntu and Windows.

## Contributing

Add a new detector as one file in `src/repodoctor/detectors/` exposing `detect(path: Path) -> list[Requirement]`, then import it and add it to the `detectors` list in `run_check()` in `src/repodoctor/check.py` (environment variables are handled separately).

Run the tests after installing the dev extra:

```powershell
.venv\Scripts\pytest -v
```
